# 评估机制

> 阶段 4 交付 · Harness 的质量评估与幻觉识别。

## 一、质量检查维度（对应指令）

| 检查项 | 实现 | 说明 |
|---|---|---|
| 数据口径 | evidence["统计口径"] | 每个结果标注"有效样本内占比"等 |
| 样本数量 | evidence["样本量"]/["有效样本"] | 明确区分总量与有效样本 |
| 计算正确性 | pandas 确定性计算 | 20 用例实测全部通过 |
| 结论有数据支撑 | 样本非空才判"有依据" | 空样本判"无依据" |
| 无夸大解释 | 八段式模板限制 | 结论限制段固定声明"意向≠订单" |
| 因果推断 | 不做事后因果 | 仅描述统计，不推断因果 |
| 建议可执行 | 建议指向下钻/关注点 | 不给虚假承诺 |
| 需人工确认 | 待审核状态 + 日志 | 由界面/用户复核 |

## 二、幻觉识别机制

1. **确定性优先**：数值不经过语言模型生成，从源头消除"编数字"。
2. **无依据即拒答**：字段缺失/样本为空 → 质量评估"不通过"，明确说明，而非编造。
3. **八段式强制格式**：每个回答必须包含"数据来源/样本量/结论限制"，缺一不可。
4. **意图边界**：不支持的问题类型（如"讲访谈故事"）→ 明确拒答。

## 三、人工审核

- 每次任务的结果 + 证据 + 步骤保留在 UI"任务记录"页与 JSONL 日志。
- 用户可：查看依据 → 修改结论 → 退回错误结果 → 确认输出 → 记录修改原因。
- 当前为**半自动**：系统给出证据链，人工在界面确认（MVP 阶段）。

## 四、对照测试（普通 Prompt vs Harness）

| 指标 | 普通 Prompt（裸 LLM） | Harness（本项目）|
|---|---|---|
| 数值准确率 | 不稳定，易编造 | 100%（20/20 用例实测）|
| 证据可追溯率 | 低，无来源 | 100%（每个回答带来源+样本量）|
| 无依据结论比例 | 高 | 0（空样本拒答）|
| 任务完成率 | 依赖模型 | 20/20 |
| 执行耗时 | 秒级（API） | 毫秒级（本地确定性）|

> 说明：当前未接入大模型 API，故"普通 Prompt"列为**设计对照**；Harness 列为**实测值**。接入 API 后可在同一问题集上做真实对照。
