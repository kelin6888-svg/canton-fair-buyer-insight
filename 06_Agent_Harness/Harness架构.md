# Agent Harness 架构设计

> 阶段 4 交付 · 定位：AI 调研分析工作流的**执行与质量控制系统**（非多 Agent 系统）。

## 一、设计原则

1. **单 Agent + Workflow**：不为了技术名词开发复杂多 Agent，只用一条清晰、可检查、可运行的流程。
2. **确定性优先**：数值一律来自 pandas 确定性统计，AI 只做意图识别与解释，不得绕过计算编造数据。
3. **证据即第一公民**：每次统计都返回 `(result, evidence)`，evidence 记录数据来源/字段/样本量/口径。
4. **可审计**：每次任务落 JSONL 执行日志，可回放、可复核。

## 二、架构分层

```
┌─────────────────────────────────────────────┐
│  交互层（Streamlit UI）                     │
│  数据概览 · 洞察 · AI问答 · 任务记录 · 报告  │
└──────────────────┬──────────────────────────┘
                   │ 调用
┌──────────────────▼──────────────────────────┐
│  Harness 工作流（harness.py）               │
│  识别类型 → 确认数据 → 字段/样本检查        │
│  → 确定性统计 → 证据检查 → 质量评估 → 日志  │
└──────────────────┬──────────────────────────┘
                   │ 调用
┌──────────────────▼──────────────────────────┐
│  工具层（analysis.py + data_loader.py）     │
│  大洲分布/国家Top/单选分布/多选计数/满意度   │
└──────────────────┬──────────────────────────┘
                   │ 读取
┌──────────────────▼──────────────────────────┐
│  数据层（7 份问卷脱敏 CSV + 数据字典）       │
└─────────────────────────────────────────────┘
```

## 三、核心组件

| 组件 | 文件 | 职责 |
|---|---|---|
| 数据加载 | data_loader.py | 导入 7 份问卷、质量检查（行数/列数/缺失）|
| 统计引擎 | analysis.py | 5 类确定性统计，返回结果+证据 |
| 意图识别 | qa.py | 规则式识别 8 类问题，无 LLM 依赖 |
| 工作流引擎 | harness.py | 拆解任务、串联工具、质检、写日志 |
| 报告生成 | report_gen.py | 自动生成可追溯报告 |
| 配置 | config.py | 路径、问卷注册、国家标准化 |

## 四、为什么不搞多 Agent

- 需求是"调研分析"，不是"多角色协作"，单 Agent 已足够。
- 多 Agent 增加编排复杂度与不可控性，违背"可检查、可复现"原则。
- 指令明确要求：先做清晰可运行的单 Agent + Workflow。

## 五、扩展点（未来可加，非当前）

- 大模型 API：仅用于理解自由文本问题（环境变量可选），数值仍走确定性引擎。
- 更多工具：历史届对比、分市场下钻（需对应字段）。
